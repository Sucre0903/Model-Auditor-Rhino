# Model Auditor 0.9.4 技术说明

## 构建与安装

脚本在每次运行时创建独立的本机临时构建目录，排除同步目录中遗留的生成文件。先还原依赖，再执行 Release 构建。遇到 `NETSDK1064` 时使用独立的临时包目录重新还原并重试。成功构建后才复制插件和更新 Rhino 注册。仅构建时，产物仍输出到源码目录内的 `bin/Release/net8.0-windows`。

## 扫描与文档生命周期

Rhino 文档表、对象和几何只在 UI 线程读取。Eto 定时器以约 12 毫秒的读取预算分时枚举对象，扫描结果只保留对象 ID、图层 ID、包围盒和诊断字段。单次 Rhino 原生调用由宿主完成，其耗时可能超过单批预算。快照完成后，后台线程计算图块、图层、风险评分以及初始排序。

读文档和汇总期间都可以停止。只有与当前扫描关联且仍有效的结果才会提交到面板。文档切换、对象结构或属性变化、图层结构以及图块定义变化都会使结果失效。单纯的对象或图层隐藏、锁定状态按定位时的实际状态处理。

## 视口定位、图层与排序

- Rhino 实际选择按当前可选状态进行。临时 `DisplayConduit` 仅在当前文档的目标视口绘制对象包围盒。示意由清除按钮、切换条目、切换文档或关闭面板解除。缩放直接使用可选对象与示意对象的范围。
- 以图层 GUID 汇总结果。点击图层链接后，在当前文档中解析 GUID 并用 Rhino 原生图层面板的选择接口高亮该行。按父级 GUID 从外到内展开目标分支，待原生图层树刷新后确认目标是否选中。此动作只涉及图层树展开和列表选择。图层显示复杂度按顶层对象所在图层归集。
- 图标作为多分辨率 ICO 嵌入插件程序集。Rhino 启动时注册面板，首次有活动模型后在图层面板旁停靠一次，后续沿用 Rhino 的面板布局。
- 下拉菜单切换五种结果。顶栏和底栏的按钮按内容宽度排列，表格保留横向滚动。
- 结果表读取原始诊断字段，列值格式化与排序键分开。点击标题后后台排序，结果提交前确认该请求仍有效，并按行对象的身份恢复全部选中行。

- 视口定位合并选中行对应的直接物件与顶层块实例。所选图层按 GUID 匹配直接和块内物件。多个定义共享祖先时只遍历一次，最终按对象 ID 去重。

## 图块与诊断

- 图块定义按 GUID 建图，每条父定义到子定义的边记录引用数量。先汇总单实例显示复杂度，再从顶层引用传递实际实例数。共享子块的各条路径分别计入，未放置定义的展开负载为零。
- **自身累计负载**是定义直属几何复杂度乘以实际实例数。**单实例含子块**包含下级引用的复杂度。文档总显示复杂度使用顶层对象，避免重复叠加。
- 定位沿父引用查找顶层对象并去重。循环、缺失引用和实例数上限会提示。链接块按 Rhino 已载入的数据统计。
- 「小而重」按顶层对象在模型中的相对尺寸和显示复杂度评分。无有效包围盒的对象跳过尺寸评分。0.9.0 保留 0.2.0 的工程阈值，真实项目校准仍待完成。
- 属性面板保留受限文本预览。CSV 导出属性计数和估算字节，第三方 UserData 只统计条目数量。
